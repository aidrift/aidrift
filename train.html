Software & Training 🧠

The Drift43 stack runs state estimation and control onboard at 100 Hz, with an overhead camera providing ground-truth localization for training and evaluation.

Pipeline overview

📡

1 — State Estimation

IMU yaw rate and acceleration fused with overhead ArUco poses give the full drift state: velocity, side-slip angle β, and yaw rate.

🎮

2 — Drift Control

A baseline controller stabilizes the drift equilibrium (counter-steer + throttle modulation); a learned policy handles transitions and recovery.

🔁

3 — Learning Loop

Policies are trained in a lightweight simulator fitted to logged data, then fine-tuned on hardware with real rollouts.

Quick start

Clone the repository, install dependencies, and run your first drift. 

# clone and install
git clone https://github.com/YOUR-ORG/drift43.git
cd drift43
pip install -e .

# calibrate the car (car stationary, on the track)
python -m drift43.calibrate --port /dev/ttyUSB0

# start overhead tracking
python -m drift43.tracker --camera 0 --marker-size 40

# run the baseline drift controller
python -m drift43.run --controller equilibrium --radius 0.6

# train a policy in simulation, then deploy
python -m drift43.train --config configs/drift_circle.yaml
python -m drift43.run --controller learned --checkpoint runs/latest

Evaluation tasks

Standard tasks for comparing controllers across builds and labs.

🌀 Sustained Circular Drift

Hold a constant-radius drift for 30 s. Metrics: mean side-slip angle, radius tracking error, recovery count.

♾️ Figure-Eight

Chain left and right drifts through the crossover. Metrics: transition time, success rate over 20 attempts.

🅿️ Drift Parking

Slide into a marked box from a straight approach. Metrics: final pose error, overshoot.

👯 Tandem Drift

Two cars hold formation through a drift sequence. Metrics: spacing error, collision-free rate.
